# 真实波传播系统开发设计

本文档保存信号传播系统的设计讨论。当前波源、传播与加工规则见第 23 节链接的实现说明。

本文档中的“波”同时覆盖机器读取的信号与能够作用于实体的冲击波。两者不是同一次爆炸生成的两个无关系统，而是同一个传播过程的不同接收结果。

第 1～22 节是当时的讨论记录；当前实现以第 23 节链接的说明为准。

## 1. 改造目标

现有信号只计算源到目标的传播成本，目标会在信号产生的同一 tick 立即收到结果。改造后的系统必须满足：

- 波具有有限传播速度，距离越远，到达越晚。
- 普通空间传播使用欧氏距离，不再使用曼哈顿距离。
- 信号到达设备与冲击波到达实体使用同一个波源、传播速度、距离和到达时刻。
- 瞬态波具有可观察的扩张波前，实体只在波前穿过时受到作用。
- 连续波在目标处体现传播延迟造成的相位偏移。
- 波源的启动、参数修改和关闭都按传播速度向外传递，不能瞬间影响远处目标。
- 保持按 `ServerLevel` 隔离的运行时状态和明确的卸载清理。
- 不为普通空间传播执行全世界三维 BFS，不强制加载未加载区块。
- 高频波源和终局爆炸阵列必须有可扩展的运行时表示，不能为每个波峰扫描全部接收端或全部方块。

## 2. 已确认的设计结论

以下内容作为本次改造的既定方向：

1. 普通空间传播距离改为欧氏距离。
2. 波不再瞬间到达，必须具有有限传播速度。
3. 设备信号与实体冲击来自同一个传播过程，并在时间和空间上同步。
4. 普通方块暂时继续沿用现有规则，不因遮挡改变传播路径或传播成本。
5. 普通空间不采用逐方块 BFS，而采用解析式球形波前。
6. 波的权威结算只在服务端完成；客户端只重建表现，不决定伤害、冲量或机器输入。
7. 运行时状态属于当前 `ServerLevel`，不新增跨维度静态可变仓库。
8. 取消独立的无形波传播体系，爆炸与机器的波使用统一的传播与到达结果。
9. 保留脉冲波与周期波；周期波随科技解锁，周期是正整数 tick，保留相位。
10. 周期为 1 tick 的周期波不产生实体冲量和伤害；周期大于 1 tick 的周期波参与实体冲量和伤害结算。
11. 同一次发射经不同路径先后到达时分别计算，不再只保留幅值最大的唯一贡献。

第 4 条意味着第一阶段的波可以穿过空气和普通方块。这不是对真实声学或爆炸物理的完整模拟，而是对现有信号传播规则的延时化和空间化。墙体、防爆材料、反射、绕射和不同介质属于后续扩展。

## 3. 为什么不使用全世界 BFS

完整三维 BFS 适合表达逐格介质、绕射、反射和不规则阻挡，但当前普通传播不判断遮挡。在这个规则下，BFS 得到的主要结果仍然只是距离，却需要访问半径内大量方块。

波半径为 `r` 时：

- 完整体积扫描的规模接近 `O(r^3)`。
- 只处理球壳仍会接近 `O(r^2)`，并需要访问大量没有接收端的方块。
- 多个高频波同时存在时，成本会随活跃波数量叠加。
- 终局高频爆炸阵列会持续制造新波，使逐波逐格传播不可接受。

解析式波前只计算当前半径，并查询可能被这一层波前穿过的接收端和实体。其成本主要与“活跃波数量 + 实际候选接收对象数量”有关，而不是与球体内方块总数有关。

BFS 仍可用于边界明确的特殊网络，例如导管内部最短路径。导管 BFS 只遍历导管网络，并可在拓扑变化时缓存结果，不等同于对世界空间执行 BFS。

## 4. 核心传播模型

### 4.1 波源

波源描述一次发射或一个持续发射状态，至少需要表达：

```text
id
维度
源位置
发射或生效 tick
初始幅值
传播速度
每格衰减
周期
相位
波形
波的持续类型
实体效果配置
来源类型与来源对象
```

建议在概念上区分：

- `PulseWaveEmission`：爆炸等事件产生的一次瞬态波。
- `ContinuousWaveSource`：机器产生的连续波列。
- `WaveSourceRevision`：连续源的启动、参数修改或关闭记录。

源的修改不能覆盖全部历史状态。远处目标在修改波前到达前仍应读取旧状态，因此运行时至少要保留仍可能影响世界的源版本。

### 4.2 欧氏距离

方块目标使用方块中心，实体目标使用其效果采样点。默认采样点可取实体包围盒中心，后续可按实体类型调整。

```text
distance = sqrt(dx * dx + dy * dy + dz * dz)
```

为继续使用整数信号幅值，普通空间的衰减成本建议定义为：

```text
attenuationCost = ceil(distance * attenuationPerBlock)
effectiveAmplitude = sourceAmplitude - attenuationCost
```

当 `effectiveAmplitude <= 0` 时，波不能对该目标产生有效贡献。

`attenuationPerBlock` 应属于传播配置。第一阶段可以使用与现有规则等价的每格衰减 `1`，但不应把该数值散落在接收端或实体效果代码中。

### 4.3 传播时间

传播时间与幅值衰减是两个独立概念，不能继续用一个 `propagationCost` 同时隐含表达。

```text
travelTicks = ceil(distance / propagationSpeed)
arrivalTick = emissionTick + travelTicks
```

其中 `propagationSpeed` 的单位为“格每 tick”。具体默认速度和不同传播介质的速度留待数值设计确认。

传播结果至少应包含：

```text
到达 tick
传播距离
幅值衰减成本
有效幅值
到达方向
传播路径类型
原始波 id
```

### 4.4 瞬态球形波前

瞬态波不需要创建 Minecraft 实体。服务端运行时保存活跃波，在每个世界 tick 计算：

```text
previousRadius = speed * previousAge
currentRadius = speed * currentAge
```

当目标与源的距离满足以下条件时，表示波前在当前 tick 穿过目标：

```text
previousRadius < distance <= currentRadius
```

同一发射的同一路径波前对同一实体或方块接收位置只结算一次；不同路径的到达不得被同一个原始波 id 误去重。脉冲的快速衰减包络持续多久尚待确认，不能仅因前沿到达最大距离就截断仍有效的波尾。上述半径公式仅描述外扩正波，反波需按第 19 节确定其形成方式后补充内收模型。

### 4.5 连续波与延迟采样

连续波不应被实现为每个 tick 创建一个新的完整球形波对象。目标在时间 `t` 读取的应是源在更早时刻的状态：

```text
sourceSampleTick = t - travelTicks
targetValue(t) = attenuated(sourceValue(sourceSampleTick))
```

因此传播会自然产生相位延迟。幅值、周期、相位和波形仍然需要表达，但旧的“仅偶数周期、正负两半的离散方波”不能原样作为新体系的唯一实现：新周期允许 1 tick 与奇数整数 tick，正反波还有明确的空间传播方向，需要重新确定波形和 tick 内采样／结算规则。

连续源启动后，其首个有效波前逐渐扩大。波前尚未到达的位置不能读取该源。源关闭或参数变化时，也会产生一个向外传播的状态变更波前：

- 关闭波前到达前，远处目标继续读取关闭前的波形。
- 参数更新波前到达前，远处目标继续使用旧幅值、周期、相位和波形。
- 更新波前到达后，目标切换到对应的新源版本。

这要求连续源仓库从“只保存当前状态”演进为“当前状态 + 尚未传播完毕的有限历史版本”。历史版本在其影响不可能再到达任何有效目标后清理。

## 5. 统一到达事件

机器信号和实体冲击应从统一的波到达结果派生。建议的逻辑流程为：

```text
WaveSource
→ WavePropagationService
→ WaveArrival
→ SignalArrivalConsumer
→ EntityWaveImpactConsumer
→ ClientWavePresentation
```

`WaveArrival` 是传播层输出的不可变值对象。传播层只回答“何时到达、到达时多强、从哪个方向到达”，不直接决定某种机器如何生产，也不直接硬编码某类实体受到多少伤害。

方块信号消费者把到达贡献提交给聚合服务。实体消费者根据同一到达幅值和方向计算冲量、伤害或状态效果。这样可以保证玩家看到的波前、实体被推动的时刻和设备收到脉冲的时刻一致。

## 6. 实体冲击模型

第一阶段至少区分以下结果：

- 机械冲量。
- 伤害。
- 客户端表现，例如声音延迟、画面震动或短暂耳鸣。
- 特殊实体响应，例如苦力怕、掉落物、矿车、投射物和玩家的不同系数。

冲量和伤害必须使用独立阈值与系数。强冲量不必然意味着高伤害，便于后续实现爆炸交通、机械驱动和非致命测试设备。

概念公式可以采用：

```text
impulse = max(0, effectiveAmplitude - impulseThreshold) * impulseScale
damage = max(0, effectiveAmplitude - damageThreshold) * damageScale
```

冲量方向默认沿源位置指向实体采样点。垂直分量、最大速度、玩家与非玩家修正、护甲和冲击抗性属于实体效果策略，不属于传播层。

同一发射、同一路径的瞬态波需要保证对同一实体单次命中；不同路径后续到达允许再次结算。正反波不能共用“半径只会增长”的命中假设。命中记录需要包含发射与路径身份，具体结构应根据活跃波数量和实体数量评估。

原版爆炸已经立即造成实体伤害和击退。正式接入时必须避免原版结算与延迟冲击波重复命中。第一阶段建议只让模组可控爆炸完整接管实体效果，不立即接管所有原版及其他模组爆炸。

## 7. 接收端索引与查询

现有接收端索引使用全局集合，并通过曼哈顿距离过滤。改造后不应在每个波 tick 对全部接收端执行欧氏距离计算。

接收端索引应按区块或区段建立空间桶，例如：

```text
dimension
→ chunk/section key
→ receiver positions
```

波前推进时先计算当前球壳的包围盒，只访问与包围盒相交且已加载的空间桶，再对桶内目标执行精确欧氏距离判断。

实体使用服务端世界已有的 AABB 实体查询。先查询当前外半径包围盒内的实体，再通过内外半径和欧氏距离过滤。不得遍历维度内全部实体，也不得为了波传播强制加载区块。

对于同一 tick 内的大量波，应考虑按空间区域对候选查询进行合并或复用，但第一阶段先保证单波查询正确，再根据实际分析结果优化。

## 8. 聚合与信号语义变化

现有聚合规则可以继续作为到达目标后的结算规则，但贡献集合的形成方式需要改变：

- 瞬态贡献从前沿到达目标时开始，按脉冲时间包络快速衰减；包络长度与 tick 内采样方式待确认。
- 连续贡献只在启动波前已经到达且关闭波前尚未到达时存在。
- 连续贡献的瞬时采样使用延迟源时间，而不是目标处当前时间。
- 不同位置会因传播时间不同而出现不同相位。
- 多个源仍在目标位置聚合，机器不需要逐个读取源。

原有 `DeliveredSignal` 中单一的 `propagationCost` 不足以表达新语义。后续需要将传播距离、衰减成本、传播时间、到达方向和路径类型分开表达。

旧的“脉冲持续 `1 tick`”不再直接限定新脉冲的形状。新定义是陡升沿后快速衰减的脉冲；其有效包络长度独立于传播寿命和周期波的周期，具体长度待确认。

## 9. 导管传播

导管仍然是内部无损的特殊传输网络，但真实波传播要求导管同时表达损耗与时间：

- 进入导管前按普通空间计算欧氏距离、衰减和传播时间。
- 导管内部可以保持幅值无损。
- 导管内部必须具有有限传播速度，不再默认瞬间跨越任意长度网络。
- 离开导管后按普通空间继续计算欧氏距离、衰减和传播时间。
- 接口仍是导管与外界交换波的唯一位置。

现有导管缓存只关心连通分量和最小外部衰减成本。后续需要增加网络内部路径长度查询。该查询可以沿导管方块执行 BFS 或 Dijkstra，但结果应由拓扑缓存持有，并只在导管或接口拓扑变化时失效。

导管路径至少需要返回：

```text
入口接口
出口接口
入口空间距离
导管内部路径长度
出口空间距离
总传播时间
总衰减成本
```

导管多路径已确定允许分别到达、分别结算：较早但较弱的直达波与较晚但较强的导管波均保留。同 tick 到达的贡献如何聚合、同网络不同出口的路径身份与回流限制仍需补齐；不能把路径去重重新实现成“同源只取最强一次”。

## 10. 运行时结构建议

建议在职责上建立波传播运行时，并由当前维度生命周期统一管理：

```text
content/explosion/wave/
├─ WaveSource / WaveEmission
├─ WaveSourceRevision
├─ ActivePulseWave
├─ WaveArrival
├─ WavePropagationProfile
├─ WaveEffectProfile
├─ WavePropagationService
├─ EntityWaveImpactService
└─ runtime/WaveRuntime
```

`content/energy/signal` 继续负责信号定义、采样、聚合和机器接收。波传播层负责空间、时间和到达结果，不能把生产配方或具体机器行为吸收到波运行时中。

`WaveRuntime` 可以由现有 `SignalRuntime` 组装，或者与其共同由更高层的维度工业运行时持有。无论最终采用哪种装配形式，都必须满足：

- 每个 `ServerLevel` 独立。
- 维度卸载和服务器停止时完整清理。
- 不持久化可由世界和源状态重新推导的临时波前。
- 对确实需要跨保存恢复的持续源，权威状态仍归属源方块实体；运行时在加载后重建。

## 11. 客户端表现与网络同步

服务端只需在波生成、源版本变化或特殊路径输出时发送紧凑事件。客户端根据以下数据自行重建视觉和听觉表现：

```text
波 id
源位置
发射 tick
传播速度
最大有效距离
表现类型
必要的强度参数
```

客户端不应每 tick 接收完整波前位置。视觉半径可以根据服务端时间和发射时间计算。

声音也应体现传播时间。远处玩家不能在爆炸发生瞬间听到完整冲击声。具体可采用立即的弱视觉提示与延迟主声，或完全按波到达时播放，后续结合实际体验确定。

客户端粒子、屏幕震动和声音不参与服务端命中判断。服务器仍以精确的波到达 tick 进行实体与设备结算。

## 12. 高频波与性能边界

活跃瞬态波数量大致等于“单位时间发射数 × 波的有效寿命”。终局阵列可能让该数量快速增长，因此需要以下约束：

- 波达到最大有效距离后立即清理。
- 不扫描波球体内全部方块。
- 接收端使用空间索引。
- 实体使用当前球壳包围盒查询。
- 未加载区块不参与普通传播结算，也不被强制加载。
- 连续波使用延迟采样，不为每个周期或每个 tick 创建独立完整波对象。
- 同源、同配置、高频脉冲可在后续表示为波列或批次，减少对象数量。
- 客户端表现设置独立密度上限，不能因粒子降级改变服务端逻辑。

若后续加入墙体、反射或不同介质，应优先采用混合模型：普通区域继续使用解析式传播，只在特殊边界附近执行局部、受预算限制的传播计算。不得直接把整个维度退回到逐格 BFS。

## 13. 分阶段实施建议

### 阶段一：纯传播模型

- 建立不可变波源、传播配置和到达结果。
- 实现欧氏距离、衰减、传播时间和球壳穿越的纯计算。
- 为连续波实现延迟采样与传播相位偏移。
- 暂不接入世界实体和机器。

### 阶段二：爆炸瞬态波

- 将模组可控爆炸转换为活跃球形波前。
- 接入实体冲量与伤害策略。
- 处理原版爆炸实体效果的替代，避免双重命中。
- 加入基础客户端扩张表现和延迟声音。

### 阶段三：方块信号接收

- 将接收端索引改为空间索引。
- 让脉冲信号在波前到达 tick 提交贡献。
- 修改聚合上下文，使传播延迟参与采样。
- 保持同 tick 到达贡献的统一聚合与延迟刷新。

### 阶段四：连续信号

- 引入连续源版本历史。
- 让启动、更新和关闭状态以波前传播。
- 只刷新已经被连续波覆盖的加载接收端。
- 验证不同距离目标的相位延迟和源更新延迟。

### 阶段五：导管传播

- 为导管网络增加内部路径长度与传播时间。
- 接口负责波的注入和输出。
- 实现拓扑变化后的路径缓存失效和受影响到达事件更新。
- 根据已确认的多路径规则处理直达波与导管波。

### 阶段六：性能与高频波列

- 使用实际分析工具确认活跃波、实体查询和接收端查询成本。
- 为高频同类波引入波列或批次表示。
- 为终局阵列建立服务端预算、诊断数据和客户端表现降级策略。

## 14. 验证要求

纯逻辑验证至少覆盖：

- 欧氏距离和整数衰减边界。
- 不同传播速度下的到达 tick。
- 高速波单 tick 跨越多个方块时不会漏掉目标。
- 目标恰好位于内外半径边界时只结算一次。
- 连续方波在不同距离下产生正确相位延迟。
- 连续源启动、修改和关闭不会瞬间影响远处目标。
- 多个脉冲在同 tick 到达时正确聚合。
- 波达到最大有效距离后正确清理。

世界生命周期验证至少覆盖：

- 实体移动进入或离开当前波壳时的命中语义。
- 实体死亡、传送、切换维度和卸载时不留下失效引用。
- 接收端区块卸载后不被刷新，重新加载后能恢复正确状态。
- 波不强制加载远处区块。
- 维度卸载和服务器停止后不存在活跃波遗留。
- 多人环境下服务端冲量权威且客户端表现一致。
- 高频爆炸下不存在无界增长的波、命中记录或源版本历史。

导管验证至少覆盖：

- 入口和出口的普通空间距离使用欧氏距离。
- 导管内部幅值无损但具有传播时间。
- 接口变化会使相关路径和计划到达失效。
- 网络拆分、合并和区块卸载不会产生幽灵输出。
- 同源直达和导管路径遵守最终确定的多路径规则。

## 15. 与现有设计文档的关系

本次改造会主动修改以下旧规则：

- “普通介质按曼哈顿距离衰减”改为按欧氏距离衰减。
- “脉冲在产生 tick 内完成传播与结算”改为在波前到达每个目标的 tick 分别结算。
- “连续信号按当前世界 tick 采样”扩展为按传播延迟后的源时间采样。
- 导管内部从只表达无损传播扩展为同时表达无损和有限传播时间。

以下规则继续保留：

- 信号拥有幅值、周期、相位和波形。
- 普通方块当前不阻挡传播。
- 导管只能通过接口与外界交换信号。
- 机器读取目标位置上的聚合结果。
- 变化产生的接收端刷新在统一调度中合并去重。
- 世界运行时按 `ServerLevel` 隔离并在生命周期结束时清理。
- 接收设备不自行恢复全局扫描 ticker。

当本开发文档中的关键决策确认后，需要同步修订 `AGENTS.md`、`README.md` 和 `docs/design_draft.md` 中已经被替代的稳定规则，不能让新实现与旧文档长期并存冲突。

## 16. 待确认决策

以下问题会改变底层数据结构或传播语义，应在实现前确认：

1. 默认普通空间传播速度是多少格每 tick，速度是否由波源或波类型配置。
2. 距离衰减采用 `ceil(distance)`、`floor(distance)` 还是其他离散规则。
3. 实体采样点使用包围盒中心、眼睛位置还是按实体类型定义。
4. 普通墙体第一阶段完全透明是否正式确认；防爆方块是否从第一阶段就影响冲击波。
5. 冲击波是否影响掉落物、投射物、载具和非生物实体。
6. 周期波的实体作用已确认按周期区分：1 tick 不产生冲量和伤害，大于 1 tick 参与结算；伤害、冲量阈值和触发频率仍需确定。
7. 导管内部传播速度，以及是否与普通空间使用同一速度。
8. 导管出口是否向空间重新释放能够作用实体的冲击波。
9. 多路径已确认：直达和导管路径先后到达时分别计算。
10. 分别到达的有效脉冲是否各触发一次生产，还是继续沿用聚合信号上升沿规则。
11. 多路径下如何定义路径身份，并限制同一导管网络的回流和重复贡献。
12. 实体移动与波前相交时，命中应依据当前 tick 位置、运动线段与球壳相交，还是采用更简单的包围盒中心采样。
13. 未加载区块中的瞬态波是否直接跳过，还是只按时间推进并允许波到达已加载的远端区块；后者可能形成视觉上跨越未加载区域的传播。
14. 模组是否只接管自身爆炸，还是最终接管原版 TNT、苦力怕以及其他模组爆炸的实体作用。
15. 反波的形成方式与起始半径；一个周期是否包含外扩和内收，还是仅表达发射重复间隔。
16. 陡升沿脉冲的衰减包络长度、反波内收时的幅值变化，以及奇数周期和 1 tick 周期的采样／机器结算规则。

## 17. 当前推荐结论

在待确认项完成讨论前，建议采用以下开发默认值作为方向，而不是最终平衡数值：

- 普通空间使用解析式球形波前。
- 欧氏距离同时决定传播时间和普通空间衰减，但两者保存为独立字段。
- 普通方块暂时透明，不执行遮挡 BFS。
- 瞬态爆炸波逐 tick 推进球壳并查询实体与方块接收端。
- 连续波通过延迟时间采样表达，不创建无限波峰对象。
- 接收端索引改为按区块或区段分桶。
- 导管内部允许在拓扑缓存上进行受限路径搜索，不扫描普通世界体积。
- 第一阶段只让模组可控爆炸替代原版即时实体作用。
- 导管按已确认的多路径方向设计；路径身份、回流限制和出口实体冲击的细节在确认前不进入实现。

## 18. 爆炸冲击波视觉实现

### 已确认的表现方向与范围

- 参考 CS2 C4 的空气扭曲感，波面若隐若现，以背景折射和极淡边缘为主。
- 波扫过玩家时允许明显、短促的镜头震动，并快速衰减。
- 先完成 TNT／苦力怕爆炸的表现，再统一机器信号到达时间。
- 以 Minecraft 原版渲染为基准，第三方光影兼容不作为此阶段承诺。
- 波速继续使用现有服务端配置。视觉波壳厚度只控制表现，不扩大伤害或信号范围。

视频参考：[CS2 New Update - Bomb Shockwave Explosion](https://www.youtube.com/watch?v=wfm5Y8Fk8WQ)。参考点是爆点之后向外推进的背景扭曲与到达视角时的冲击感；以下渲染方法是本模组的实现，不代表 Valve 内部算法。

### 客户端分工

- `ClientPulseWave`：保存服务端发射数据、重建半径与强度、记录本地玩家是否已获得反馈。
- `ClientPulseWavePresentation`：接收发射数据，驱动表现生命周期，协调本地反馈与绘制。
- `PulseWaveRenderer`：选择可见波、管理场景拷贝、提交着色器参数并恢复渲染状态。
- `PulseWaveFeedback`：一次性的空气冲击声与俯仰、偏航、翻滚震动，不决定实体伤害和击退。

上述类统一放在 `client/explosion/wave/`。注册入口仍为 `CreeperIndustryClient`，服务器传播与网络载荷不依赖客户端类型。

### 折射与遮挡

1. 在 `RenderLevelStageEvent.Stage.AFTER_LEVEL` 获取世界颜色与深度，此时世界透明合成已完成，手持物与 HUD 尚未绘制。
2. 将颜色与深度一次拷贝到独立缓冲区，避免边写主目标边采样同一纹理。
3. 以相机相对坐标、投影和视图矩阵重建每个像素的视线，与扩张球面求交；相机在球内时使用离开球面的交点。
4. 场景深度限制可见波面：前景表面位于波面之前时，该像素不受波折射。波传播仍可穿过普通方块，渲染遮挡不改变传播语义。
5. 通过球面法线产生小幅背景位移，轮廓处较强，辅以低强度连续扰动与淡亮边缘；多波位移与亮度统一限幅。
6. 按世界时间与 partial tick 平滑推进。波的末 tick 保留到插值结束，但不延长实体反馈判定窗口。

透明玻璃、水面等材料的深度与排序取决于原版渲染路径，仍需在各画质模式下实机核对，不能将编译通过视为视觉兼容验证。

### 反馈与成本

- 移除原先沿球面随机生成的 CLOUD／SMOKE 粒子。
- 保留原版爆点声音；波到达本地玩家时用低音调、低音量的原版风弹空气声提供提示，不再次播放完整爆炸音。
- 镜头震动由到达幅值决定，短时衰减；多个冲击叠加有上限。折射与震动不受原版屏幕效果强度滑块影响，也不提供游戏内强度调节入口。
- 波面采用加强的背景折射；玩家收到冲击后另有径向扭曲和最多 12 tick 的模糊恢复过程，波面离屏或结束后仍完成衰减。模糊仅在本地受击期间增加固定的 8 次颜色采样，与原折射共享缓冲区和合成过程；不会为其他实体创建镜头效果。
- 客户端最多跟踪 128 道波，每帧选择最多 8 道可见且影响较大的波，在单次合成中处理；降级只影响表现。
- 暂停时不推进本地反馈；维度／世界切换、退出、关闭游戏和着色器重载时清理表现；窗口尺寸或深度格式改变时重建场景缓冲区。
- 服务端原有波速、衰减、伤害、击退、方块破坏与机器信号链此次均不调整。

### 验证边界

编译与资源检查包括 Java 构建、GLSL 150 顶点／片元编译和链接，以及 shader JSON 的 uniform、sampler 对应关系。

游戏内需人工核对：近中远距离 TNT 和苦力怕、侧视波面、相机位于球内、爆心离屏、墙后波面、玻璃与水面、快速／高品质／极佳画质、多波同时出现、暂停恢复、窗口缩放、F3+T 重载、维度切换与重新进入存档。观察波面位置、界面清晰度、镜头强度、声音重复与资源残留。本轮未自动启动客户端、服务器或游戏动态测试。



## 19. 上一轮统一有形波体系设定（重新评估中）

### 上一轮讨论的玩法定义

- 正波指从中心向外扩散的波；反波指由外向中心聚拢的波。
- 保留周期和相位，但“正波／反波”的空间传播方向需要独立表达，不能仅把旧瞬时采样值改成负数就视为反波。
- 原版爆炸产生陡升沿后快速衰减的脉冲。
- “连续”描述时间上的持续表现。密集、持续不断的脉冲也可以形成连续波，不能以是否连续来区分来源类型。
- 需要作为正式类型保留的是脉冲波与周期波。周期波由玩家推进科技解锁，具有周期和相位；具体科技解锁内容另行设计。
- 机器可以发出脉冲波或周期波。周期使用正整数 tick；在整数 tick 模型中，正周期小于等于 1 tick 仅对应 1 tick，0 不能作为合法周期。
- 周期为 1 tick 的周期波不产生实体位移和伤害；周期大于 1 tick 的周期波参与位移与伤害结算，具体强度仍受效果规则约束。
- 同一次发射经不同路径先后到达时，分别计算。

### 对实现的直接要求

- 从波源定义中移除对非空原版 Explosion 的强制依赖；爆炸归因与兼容信息作为来源上下文保留，机器波不能伪造爆炸来接入。
- 波向、时间包络、周期、相位、传播速度、传播距离／边界分别表达；周期与整个波的传播寿命不能在未确认的情况下合并。
- 现有仅允许 2／4／6／8 tick 的周期限制需要迁移。1 tick 与奇数周期的波形及取样必须重新设计，不能直接塞入旧方波采样器。
- 是否免除实体冲量和伤害按正式波类型和周期判断，不能因一串普通爆炸脉冲在时间上连续就自动改变其类型。
- 接收数据需要同时携带原始发射身份与传播路径身份。同一路径重复查询应去重，不同路径的新到达应保留。
- 生态瓶等多方块应在控制器统一处理到达身份；同一波经过不同组成块不应误计为多次独立输入，不同路径则不能被原始波 id 一并消除。
- 1 tick 周期波的机器作用不能因每 tick 总采到同一相位或正负平均抵消而意外消失，需明确设备使用的幅值、周期事件或其他结算量。
- 周期波继续采用源参数与有限版本历史表达；可见波列由同一源参数重建，避免每 tick 为每个波峰创建完整全局查询对象。

### 尚待讨论，不能隐含选定

1. 正波是否到边界自动转成反波，还是正波、反波由不同机制产生；周期定义的是完整往返还是发射间隔。
2. 反波从何处开始、范围如何确定，内收时幅值维持衰减还是发生聚焦增强；向内运动不自动等于幅值无上限增长。
3. 相邻 tick 的两次有效到达是否各触发一次生产；按到达事件触发与旧聚合上升沿触发可能得到不同结果。
4. 脉冲快速衰减的包络长度与实体作用次数；不能未经确认把波尾每个 tick 都变成一次额外伤害。
5. 同 tick 多路径的聚合规则、导管循环限制与同网络多个出口的身份。
6. 1 tick 周期波仍需有形传播和机器作用；其触及玩家时是否保留屏幕冲击反馈，不能从“不推人、不伤人”自动推导。

本节记录目标规则。本次仅修订设计文档，尚未替换机器信号链、正反波传播、周期波采样或导管路由实现。

## 20. 幅值符号、快速周期波与搭建式机器

### 最新确认

- 不定义独立的正波、反波或正相波、反相波类型。正幅值沿局部传播方向推动实体，负幅值沿相反方向牵引实体；负幅值不代表波面向源点收缩。
- 周期波保留周期、相位和正负幅值变化。周期采用有限科技档位：整数档为 2、4、…、100 tick，共 50 档；小数档为 0.1、0.2、…、1.0 tick，共 10 档。用户明确 1 属于小数档。0 不是合法周期，1.5 等大于 1 的非整数周期不允许作为源档位。相位精度待定。
- 波形限制为方波。周期波使用正负交替的方波；脉冲使用有限个幅值逐级衰减的矩形时间段，形成陡升后阶梯下降的包络。时间波形不改变空间球面传播的含义，段长与衰减比例待定。
- 无冲击力／牵引力的快速周期波边界为 `0 < T <= 1 tick`。这是实体作用规则，不代表机器驱动力为零，也不能推广到独立脉冲的密集发射。
- 机器驱动需要先叠加再判定，避免逐源取绝对值破坏相消。机器有独立的生产效率参数，表示每件产物需要多少加工单位。常规有效 tick 要求合成幅值绝对值高于工作需求，且带符号合成值与上一 tick 不同；正负均可驱动。小数档周期波（含 1 tick）免除相邻 tick 幅值变化限制，每个完整有效周期贡献 1 个加工单位；T=0.1 时每世界 tick 可贡献 10 个，不限制为 1。
- 用户明确不同周期混合也按波形合成处理，机器只依据合成后的波形计算。不同源的门槛判定、有效周期数和生产倍率不能先单独计算再相加。
- 机器改为独立方块组合成建筑的形式，参考匠魂；提供若干可选的预设尺寸，不采用任意长宽高。搭配模组自带的结构生成／蓝图施工功能。各档尺寸、组件与成型条件待定。

### 当前代码观察

- `ContinuousSignalPropagationService.collectContributions` 在接收点刷新时遍历全部活动周期源。
- `DefaultSignalContributionAggregator` 对纯周期贡献重新扫描公共周期，并在每个采样点遍历贡献；开销不主要来自绝对值运算本身。
- 现有生态瓶一次放置生成固定 3×7×2 组成块，每格创建方块实体。新结构的普通外壳不应自动复制这一组织方式。

### 推荐方案，尚未确认

- 稳定周期输入预先合成为可复用的机器响应，运行时读取结果；不能每 tick 重新搜索路径并扫描公共周期。
- 保留随时间变化的干涉强弱，不以全周期平均常数代替。此前提出的每 tick 绝对值平均不自动作为最新有效 tick 规则，具体判定按第 21 节讨论。
- 波源开始、修改、停止以变化传播到接收位置的时刻切换响应。脉冲只在其到达和持续区间局部叠加，结束后恢复稳定响应。
- 公共周期、周期精度、源数量和缓存规模需要有界。已确认的整数档包含不同因子，不能展开完整最小公倍数，也不再采用此前推荐的纯倍频档位。
- 方波按幅值跳变边界分段合成，缓存每段带符号总值及时间边界，再由生产规则判门槛和累计单位。此前绝对值积分的建议不能代替已确认的变化／周期计数。无需以很小步长逐点遍历波形；输入与路径不变时复用结果。
- 阶梯脉冲作为一个具有持续包络的发射事件表达，各段不是独立爆炸。按最新有效 tick 规则，其多个幅值变化可以在不同 tick 累计生产进度，替代此前“一整个脉冲只提供一次加工机会”的建议；不能把每段直接视为一件产物。
- 建筑机器由控制器、结构外壳、专用波接收部件和物料接口组成；普通外壳不注册为波接收端，也不默认需要方块实体或 ticker。
- 第一版建议每座建筑机器设置一个有效波接收部件，以该位置的场作为输入，由控制器结算；多接收部件如何合并属于后续规则，不能直接把各点绝对值相加。
- 结构检测由建造、拆除、加载等变化触发并合并调度，限制检查范围；不每 tick 扫描整座建筑。结构破损时停止生产并保留其余组成方块，库存始终保持单点权威。
- 预设尺寸分别提供对应的官方施工模板，与玩家蓝图复用施工流程。沿用路线图中提供方块与火药、逐方块施工的方向。手工建造和自动施工应使用相同成型规则，模板与校验共享结构定义，避免各维护一份相互偏离的搭法。

本节仅更新设计讨论，不修改机器、波采样、实体作用或结构实现。旧稳定文档中的冲突规则应在对应方案确定并进入迁移时同步修订。

## 21. 有效 tick 生产的性能方案（讨论稿）

### 需要先明确的采样语义

- 严格按相邻世界 tick 的固定时刻取样，周期 0.5 tick 等波可能永远取到同一幅值，因此无法持续贡献有效 tick。每 tick 的绝对值平均也不能保证保留变化。
- 用户已确认：小数档周期波免除相邻 tick 幅值变化限制，每完成一个有效波周期贡献 1 个加工单位。T=0.1 每世界 tick 可累计 10 个；不能将正负两个边沿各算一个完整周期。
- 非整除周期保留跨 tick 的周期余量／相位，不逐 tick 舍弃小数。以持续达标且从整 tick 开始的 T=0.3 为例，连续三个 tick 的完整周期计数可为 3、3、4，共 10；实际排列取决于到达相位。产出不能预支尚未发生的周期。
- 用户已确认以合成幅值绝对值判工作门槛、以带符号合成值判断变化，负幅值允许生产。相消必须先于门槛和进度判定，快波不能绕过这一顺序。
- 1 tick 已明确归入小数档，按每完整有效周期贡献 1 单位衔接快速档；持续达标时每世界 tick 贡献 1。实体免推拉边界仍为 T<=1。
- 不同周期贡献统一合成为接收点的一条带符号阶梯波形；机器生产只读该合成波形。波源的有限档位限制不意味着合成结果仍是单一方波，也不能为了落回档位而舍入或截断合成结果。
- 此处此前待议的合成后判定已由第 22 节明确：纯快波采用合成波形的最大绝对幅值与周期，存在慢波则统一走慢波规则。不引入零点穿越或两个边沿计数来替代用户规则。
- “高于”暂按严格大于处理。相位精度、传播到达时间精度与定点幅值精度另行确定，不因为优化自动量化传播时间。

### 调度与缓存

1. 为每个有效接收点维护当前实际到达的源／路径贡献与版本，只在到达、离开、参数变化或拓扑变化影响到该位置时更新；不用每 tick 全源扫描。
2. 各路方波保存当前值和下一次跳变时刻，阶梯脉冲保存下一段边界。合成值按变化差量更新，不在每次事件重新求所有源的和。
3. 同一时刻到达的变化合并后判定，避免互相抵消的两路波因处理顺序产生虚假有效 tick。常规 tick 判定比较边界样本；快速波按完整有效周期汇总刻内结果，不能擅自限制为 1，也不能逐源生产后再相加。
4. 同周期且到达后相位一致的贡献可以合组，合组幅值为零则不调度无效重复跳变；保留源身份以支持后续修改与移除。
5. 不展开全局公共周期。整数档 2、4、…、100 的公共周期为 6198089008491993412800 tick。仅对足够小的重复片段使用缓存，其余采用有界近期窗口或逐事件计算；缓存上限与计算预算必须明确。
6. 可缓存近期有效 tick 位图／前缀计数，按接收点输入版本和工作门槛失效。快速波缓存每 tick 的整数加工单位数及前缀和，不能只用布尔位图。快速波需优先复用短周期片段，不能用世界子 tick 循环扫描所有机器。不能宣称消除了随接收点数和活跃贡献数增长的开销。
7. 波合成结果和配方相关的有效 tick 判定分开；配方门槛改变只重建判定，不重新搜索传播路径。世界运行时集中调度，建筑仅专用接收部件参与波计算。

### 生产与生命周期建议

- 控制器持有已累计加工单位与每件需求 N；常规有效 tick 加 1，快速波按完整有效周期数批量增加，达到 N 时权威检查并结算产物。每 tick 允许多次完成时，按实际材料与输出空间限制结算数量，不按加工单位逐次扫描配方或同步库存；剩余进度的堵塞处理边界仍待确定。无效 tick 暂停而不清零，是否采用此规则待确认。
- 建议材料不足、输出堵塞、结构失效时暂停累计，不囤积无限未来产物。信号采样基线继续随世界时间更新，不能因恢复材料而制造虚假波形变化。
- 可按未来有效 tick 计数预约下一次完成时刻，但只能在实际到时且条件仍有效时产出；期间输入、库存、配方或结构变化应取消或重算预约。缓存不是预先生产。
- 区块卸载时注销接收与预约，不补算卸载期间产出；恢复时建立当前波形基线，不把“未知旧值”当成零制造额外有效 tick。
- 进度持久化与界面同步分开，不因每次计数都发送方块更新；生产、库存与可见状态按需同步，打开菜单时同步进度。

本节是实现前方案，未修改生产、配方、波形或调度代码，也未运行游戏或动态测试。

## 22. 已确认的快慢分流与传播变化定向通知

### 用户明确的聚合规则

1. 纯快波：输入变化时计算合成波形，以合成波形的最大幅值和周期判断加工进度。结合此前正负均可驱动的规则，最大幅值使用最大绝对幅值；输入稳定时复用缓存。
2. 慢波：输入无变化时按缓存判断；有变化时先直接计算当前 tick 的带符号合成幅值，完成该 tick 加工判定。若参与合成的全部是周期波，再合成波形并更新缓存。
3. 快慢混合：统一退化到慢波分支，不享受快波周期倍率。因此不能通过微小幅值快波将慢波输入提升到快波级效率。
4. 快慢分支依据当前实际参与的到达贡献判断，不依据世界里是否存在快波，也不能仅用合成周期重新分类。1 tick 继续按用户此前明确的小数档归类。
5. 机器只使用接收点的合成结果；不按源分别判断工作门槛、计算产能后再相加。含脉冲时不能把有限尾部当作永久周期重复。

### “变化”与缓存的工程含义

- 使缓存失效的变化是接收点输入组成或描述发生变化：源开始、结束、幅值／周期／相位修改、路径与衰减变化、脉冲进入／结束等在该位置生效。
- 已知周期内的正负跳变属于缓存波形的正常推进，不因每次翻转而重新搜索路径或合成完整波形。
- 缓存保存带时间基准的波形／求值计划；无输入变化不等于每 tick 幅值相同。慢波仍需比较该 tick 与上一 tick 的带符号值，不能将缓存简化为一个长期不变的幅值。
- 纯快波缓存合成波形的最大绝对幅值、周期与计数时间基准；按完整周期批量累计单位。零波形不产生进度。
- 慢波纯周期组合可能有极大公共周期，缓存允许采用合成表达式与有界近期求值窗口；不要求展开全部公共周期。全周期慢波缓存不能继续使用现有 int 最小公倍数循环。
- 含脉冲时仍复用已到达的周期背景和路径贡献，按有限包络求当前值；脉冲结束后恢复纯周期缓存。无需每 tick 重新扫描全源。

### 对现有实现的核对

- `DefaultSignalContributionAggregator` 已实现带相位的有符号叠加。纯连续源分支扫描公共周期，输出绝对值平均的向上取整值，并包装成 `SignalDefinition(..., SQUARE)`；未保存真实合成波形，未计算快波所需峰值。
- 混有瞬态源时走当前 tick 叠加分支，但没有快慢分类，也没有源变化驱动的合成缓存。
- `SignalDefinition` 的周期与相位都是整数 tick；`SignalSampling` 将 period=1 特判为固定正幅值，不能表达新小数档方波。
- `SignalRuntime` 已按维度集中管理源、接收索引、刷新队列和服务。机器不是自行扫描周围；但每 tick 刷新活动目标，`ContinuousSignalPropagationService` 对每个目标遍历活动周期源。
- `DeferredSignalRefreshQueue` 只是位置去重集合，没有到达时间。`InMemorySignalAggregationService` 只是按目标和源 tick 暂存瞬态贡献，不是合成波形缓存。
- `ContinuousSignalUpdateService` 已对源修改／移除定向收集目标，但立即更新仓库并在 tick 末刷新，没有传播延迟。
- 爆炸 `WaveRuntime` 推进实体波壳并通知客户端；机器仍通过旧信号链即时接收。生态瓶仍是条件上升沿产出，并非累计加工单位。

### 统一层提前通知，到达时生效

- 在当前每 ServerLevel 的运行时中扩展传播调度职责；源变化时通过接收端空间索引和路径缓存查找实际受影响目标。机器只注册和接收通知，不自行搜索波源或检测邻域。
- 为目标记录源身份、路径身份、源版本、到达时间、变化类型及贡献快照。已有位置集合扩展为按到达时间调度的事件队列；同一时刻同一接收点的变化合并后再判定。
- 定向预告是服务器内部调度信息。可以提前准备未来缓存，并记录当前缓存的有效截止时间；当前生产仍使用已经到达的旧输入，到达时才切换贡献与缓存。不能因提前知道未来变化而提前增产、停机或更改模式。
- 源在 tick 100 改变，到达需要 20 tick，则调度层可在 tick 100 登记 tick 120 的更新；tick 120 前继续使用旧输入。源停止也发送有传播时间的结束变化，不能立即撤销所有远端旧波。
- 源再次修改不能无条件删除先前已发出且仍在途的版本；接收点应按实际到达顺序处理。预约与缓存版本用于防止重复或误用，不用于抹掉有效的旧波传播。
- 拆除接收端、区块卸载和维度关闭时清理订阅与预约；重新加载按当前传播状态建立基线。路径变化需定向修订受影响预约，不能全维度广播重算。
- 提前通知适用于已经注册、可预见到达的目标；零距离、同 tick 到达或刚加载目标可能只能在本 tick 合并处理，不能承诺始终至少提前 1 tick。
