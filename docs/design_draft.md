# Creeper Industry 设计草案

本文档用于记录当前已经确定的系统规则、实现边界和后续迭代约束。  
它不是随意发散的想法堆，而是当前代码实现应当遵守的设计基线。

## 1. 项目定位

本项目围绕以下主题展开：

- 苦力怕
- 爆炸
- 信号工程
- 高风险工业化

系统目标不是做传统电力模组，而是做一套“信号工业”：

- 爆炸可以成为早期信号源
- 机器可以成为持续信号源
- 信号可以传播、衰减、聚合、被机器读取
- 导管提供一种特殊的无损传输手段

## 2. 当前系统分层

当前内容大体分为：

- 物流系统
- 生产系统
- 信号与导管系统

目前优先级最高的是信号系统和导管系统。

## 3. 信号系统总规则

### 3.1 信号基本属性

每个信号至少包含：

- 幅值
- 周期
- 相位
- 波形

当前实现中，系统运行在离散 tick 时间上，所以所谓“连续信号”本质上仍然是离散采样波形，而不是数学意义上的连续函数。

### 3.2 信号类型

当前分为两类：

- 脉冲信号
- 连续信号

#### 脉冲信号

- 典型来源：爆炸事件
- 持续时间：`1 tick`
- 在该 tick 内完成传播与结算

#### 连续信号

- 典型来源：机器
- 会持续存在，直到源被移除或参数发生变化
- 当前波形统一为方波

## 4. 传播规则

### 4.1 普通介质传播

普通介质包括空气和普通方块。当前规则下，它们统一视作普通传播介质。

规则如下：

- 信号可以穿墙传播
- 每传播 `1` 格，幅值衰减 `1`
- 传播代价按曼哈顿距离计算

传播代价公式：

`|dx| + |dy| + |dz|`

若信号初始幅值为 `A`，传播代价为 `d`，则到达目标后的有效幅值为：

`A - d`

当有效幅值小于等于 `0` 时，视为该信号不能影响目标。

### 4.2 导管传播

导管是特殊传播介质，其定位更接近“无损信号通道”。

规则如下：

- 导管内部传播无损
- 信号进入导管前和离开导管后，仍然按普通介质规则计算传播代价
- 同一个信号源到同一个目标，只取最佳传播路径，不会把“空气路径贡献”和“导管路径贡献”各算一份

这意味着：

- 空气直达和导管绕行之间会比较代价
- 最终只保留更优的那条路径

## 5. 导管与接口规则

### 5.1 导管不是六面漏风

导管不能把自身六个面都当成天然信号源或天然输入口。

收紧后的规则是：

- 导管本体只负责网络内部无损传输
- 导管不会自动与周围空气或普通方块连通信号
- 导管只能通过接口与外界交换信号

### 5.2 接口形式

接口不是独立方块，而是导管方块上的同格挂件。

每个导管有六个面状态：

- `interface_north`
- `interface_south`
- `interface_east`
- `interface_west`
- `interface_up`
- `interface_down`

规则如下：

- 一个面要么没有接口，要么有一个接口
- 已与另一根导管直接连通的面，不能安装接口
- 接口的输入输出面就是该面的外侧相邻格

### 5.3 外界连通条件

只有存在接口的面，才允许发生以下行为：

- 空气中的信号进入导管
- 导管中的信号输出到空气
- 导管与普通方块中的信号发生连通

没有接口的导管面，一律视为对外绝缘。

### 5.4 更新规则

接口增删必须触发：

- 导管方块状态刷新
- 邻居更新
- 相关接收端重算
- 导管网络缓存刷新

接口变化不仅是渲染变化，也必须实际改变导管网络的可进入/可输出面。

## 6. 连续信号采样规则

### 6.1 当前波形

当前只实现方波 `SQUARE`。

### 6.2 周期范围

当前连续信号周期允许范围：

- `2 tick`
- `4 tick`
- `6 tick`
- `8 tick`

### 6.3 采样规则

连续信号当前统一使用偶数周期离散方波，不再支持奇数周期。

采样规则如下：

- 前半周期采样为 `+A`
- 后半周期采样为 `-A`

示例：
- `2 tick`：`+A, -A`
- `4 tick`：`+A, +A, -A, -A`
- `6 tick`：`+A, +A, +A, -A, -A, -A`
- `8 tick`：`+A, +A, +A, +A, -A, -A, -A, -A`

这样做的目的：

- 保持方波定义统一
- 避免奇数周期补丁规则污染整体系统
- 让周期语义与采样语义完全一致

### 6.4 相位规则

连续信号源正式带有相位属性。

规则如下：

- 相位取值范围为 `0 ~ period-1`
- 相位参与当前 tick 的采样计算
- 相位不是默认固定为 `0`
- 当前实现中，相位由机器位置与源 id 稳定生成

这样做的目的：

- 避免所有同周期连续信号天然同相
- 让连续信号叠加结果真正体现波形系统特性
- 缓解“全偶数周期时等效值退化成锁相主导结果”的问题

## 7. 多信号聚合规则

### 7.1 聚合对象

对某个目标位置，系统会收集所有可以有效到达该位置的信号贡献。

机器默认只读取聚合后的单一结果，而不是分别读取所有源。

### 7.2 连续信号之间的聚合

若参与聚合的全部都是连续信号，则：

1. 求出它们周期的最小公倍数作为公共周期
2. 在公共周期内逐 tick 采样各自的瞬时值
3. 对每个采样点先做带符号求和
4. 再对和取绝对值
5. 最后对整个公共周期求平均

这个平均值就是机器读取到的等效值。

### 7.3 脉冲信号参与时的规则

若某个 tick 内有脉冲信号参与，则该 tick 按瞬时结算：

- 连续信号先按各自当前相位采样
- 脉冲信号按该 tick 的有效值参与
- 全部贡献做带符号求和
- 该 tick 结果按 `|sum|` 结算

这里不为脉冲额外构造跨 tick 的公共周期。

## 8. 机器读取规则

机器默认读取的是聚合后的最终结果。

当前关键读数：

- `equivalent_value`
- `instantaneous`
- `last_non_zero`

定义如下：

- `equivalent_value`：等效值
- `instantaneous`：当前 tick 的瞬时值
- `last_non_zero`：最近一次非零等效值

进一步约定：

- 纯连续信号场景下，等效值为公共周期内叠加波形绝对值的平均
- 当前 tick 混入脉冲信号时，该 tick 的瞬时结算结果可直接影响机器当前读数
- 生态瓶的幅值与瞬时值要求由 `biosphere_cultivation` 配方中的独立信号条件声明
- 生态瓶只使用当前模板对应配方的信号条件，不允许同类型其他配方的较低门槛触发当前生产
- 消耗品缺失只阻止当前生产结算，不改变信号边沿状态；持续高信号下补入消耗品不会立即再次生产
- 生态瓶仍由机器维护上升沿状态；持续满足同一条件不会每 tick 重复生产

## 9. 更新机制

当前信号系统采用“变化驱动更新”，而不是所有接收端每 tick 主动全量轮询。

世界中的信号状态由每个 `ServerLevel` 独立拥有的 `SignalRuntime` 管理。信号源仓库、接收端索引、导管网络缓存、聚合缓存、瞬时影响记录与延迟刷新队列均属于当前维度，不使用只按维度资源键区分存档的全局单例。

触发重算的情况包括：

- 爆炸事件发生
- 持续信号源参数变化
- 持续信号源被放置、更新或移除
- 导管被放置或拆除
- 接口被安装或拆除
- 导管网络连通性变化

更新原则：

- 只重算受影响的接收端
- 导管网络变化需要刷新缓存
- 脉冲消失也算一次变化
- 连续信号源或拓扑变化时，重建当前维度内可能持续受影响的目标集合
- 同一 tick 内连续注册多个接收端时，只标记活动目标集合失效，并在集中刷新前统一重建一次
- 脉冲、连续源变化和拓扑变化产生的刷新目标先合并去重，再在世界 tick 末统一结算
- 接收端只负责注册、注销和处理聚合结果，不自行运行信号刷新 ticker
- 未加载区块不被主动扫描；已加载但不再是接收端的位置会从索引中移除

每个世界 tick 的集中处理顺序为：

1. 清理上一 tick 的瞬时信号源与聚合贡献
2. 收集上一 tick 脉冲消失后需要恢复或清零的目标
3. 合并导管与接口变化产生的延迟刷新目标
4. 合并当前连续信号活动目标
5. 对已加载接收端去重刷新，并清理失效索引

`SignalRuntime` 使用非持久化 Level Attachment。它只保存能够从当前世界重新推导的临时状态，维度卸载或服务器停止时统一清理，不写入存档。

## 9.1 信号范围破坏器

信号范围破坏器是功能性自动化设备，只负责破坏输出面外满足条件的方块，不负责收集掉落物、伤害实体或产生真实爆炸。

- 设备支持六向输出，宽度、高度和深度分别允许 `1` 或 `3`，范围从输出面外第一格开始。
- 设备自行维护信号条件激活状态，不在信号运行时中加入通用边沿服务。
- 当前有效条件为聚合等效幅值大于零且瞬时值为正；条件从不满足变为满足时执行一次，持续满足时不重复执行。
- 设本次聚合等效幅值为 `A`，配置范围完整格数为 `V`，最大可破坏爆炸抗性为 `6A / (13V)`；内部判定不提前取整或截断。
- 空气、受保护方块和强度不足方块仍计入 `V`，不会把未使用的破坏能力重新分配给其他格子。
- 目标必须位于世界边界内且区块已经加载；不可破坏硬度、免疫标签或被取消的 NeoForge 方块破坏事件都会阻止破坏。
- 所有目标先统一收集并去重，执行前重新核对方块状态，再使用服务器正常方块破坏路径生成掉落、粒子和邻居更新。
- 设备作为普通信号接收端接入集中刷新机制，不运行独立 ticker，也不主动扫描信号源。

## 9.2 爆炸气浪视觉效果

爆炸气浪是对真实爆炸事件的纯客户端表现增强，不是新的爆炸类型、实体或信号传播机制。它由服务端确认爆炸已经发生，再向附近客户端同步最小必要参数；客户端负责扩张球壳、屏幕折射、曝光、镜头冲击和生命周期管理。

### 9.2.1 视觉目标

- 爆炸发生后先出现短促闪光，随后有一层较薄、带不规则空气扰动的球形波前从爆心高速扩张。
- 波前接近相机时，已经渲染完成的方块、实体和天空画面发生短促的径向偏移与拉伸，而不是覆盖一张静态模糊贴图。
- 气浪经过后快速衰减，只留下原版或受预算限制的烟尘、火星等装饰粒子。
- 视觉强度随爆炸强度和玩家距离平滑衰减；达到最大视觉范围后直接归零。
- 完整墙体隔开玩家与爆心时不产生玩家侧气浪冲击；门洞或掩体边缘可以按可见比例减弱效果。

这里的“折射”统一指屏幕空间场景颜色偏移，不要求物理光线追踪。墙体影响统一指爆心到相机的可见性遮挡，不包含波前沿门洞、拐角或走廊绕行的空间传播模拟。

### 9.2.2 玩法与信号边界

- 气浪不修改爆炸伤害、方块破坏、击退、爆炸半径或服务端结算时机。
- 气浪不创建 `Entity`、方块实体或持久化世界对象；装饰粒子也不承担权威玩法逻辑。
- 视觉遮挡不得改变信号传播。即使墙体完全挡住气浪画面，爆炸脉冲仍按普通介质的曼哈顿距离规则传播。
- 视觉模块不得读取、写入或延长 `SignalRuntime` 的瞬时爆炸源生命周期，也不得让信号运行时依赖客户端类型。

### 9.2.3 同步与生命周期

- 在不可取消的爆炸完成阶段确认视觉事件，避免被取消的爆炸仍向客户端播放气浪。
- 服务端载荷只携带爆心、爆炸强度和视觉随机种子；维度由发送目标隐含确定，最大范围、持续时间和衰减由客户端稳定规则推导。
- 只向同维度、最大视觉范围内的玩家发送载荷，不广播到整个服务器，也不发送爆炸方块列表。
- 客户端效果状态只存在于当前客户端世界；断开连接、切换世界或资源关闭时必须清空并释放渲染资源。

### 9.2.4 遮挡与衰减

- 最大范围判断优先使用平方距离，超出范围的效果在进入活动集合前直接丢弃。
- 墙体遮挡使用固定少量的方块视线射线，而不是遍历爆炸范围内的方块。射线只在波前可能影响相机时计算，并缓存到当前气浪结束；相机显著移动时最多进行有限次数重算。
- 所有采样射线均被方块碰撞形状完整阻挡时，玩家侧球壳和屏幕冲击强度为零；部分畅通时按畅通比例衰减。
- 遮挡检测不得强制加载区块，不得建立爆炸空间导航图，也不得尝试寻找绕墙路径。
- 距离衰减、波前包络和遮挡系数在客户端组合为最终视觉强度；低于可见阈值的效果提前结束。

### 9.2.5 渲染与性能边界

- 世界气浪使用复用的单位球壳网格缩放绘制，开启深度测试、关闭深度写入，并在适合透明特效的世界渲染阶段提交。
- 屏幕折射使用模块自有的后处理资源，不替换或独占 `GameRenderer` 当前效果；在世界完成而 GUI 尚未绘制时处理主颜色缓冲。
- 每帧最多执行一次气浪后处理。多个同时到达的气浪先在管理器中筛选，再由同一 pass 处理固定数量的最强贡献。
- 活动气浪数量必须有硬上限；同一 tick、相近位置的爆炸应合并，达到上限时优先淘汰最远、最弱或即将结束的记录。
- 不在每个气浪上分别执行全屏 pass，不按爆炸数量无限增加粒子，也不每 tick 重复进行未失效的遮挡检测。
- 着色器创建、资源重载或执行失败时退化为无折射表现；失败不得影响爆炸结算、信号系统或客户端继续运行。

## 10. 当前已落实的关键实现约束

以下规则已经进入实现，不应轻易回退：

- 导管采用“同格挂件接口”方案，不再使用独立接口方块
- 导管只能通过接口与外界信号连通
- 同一信号源到同一目标只取最佳路径
- 检测器第一项显示的是等效值，不是简单意义上的“当前值”
- 连续信号只保留偶数周期
- 连续信号相位是正式规则，不再默认全部为 0
- `CISignalSourceTypes` 只负责全局只读的信号源类型声明，不持有世界运行状态
- 所有世界信号服务通过当前 `ServerLevel` 获取对应的 `SignalRuntime`
- 信号仓库、接收端索引、聚合缓存和导管缓存均为单维度对象
- 生态瓶与检测器不再拥有独立的信号刷新 ticker
- 方块实体加载与卸载必须成对注册、注销信号源或接收端
- 维度卸载与服务器停止必须释放完整信号运行时

## 11. 后续实现建议

接下来继续开发时，优先级建议如下：
