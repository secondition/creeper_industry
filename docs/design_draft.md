# Creeper Industry 设计草案

本文档用于记录当前已经确定的系统规则、实现边界和后续迭代约束。  
它不是随意发散的想法堆，而是当前代码实现应当遵守的设计基线。

## 1. 项目定位

本项目围绕以下主题展开：

- 苦力怕
- 爆炸
- 信号工程
- 高风险工业化

系统目标不是做传统电力模组，而是做一套“信号工业”：

- 爆炸可以成为早期信号源
- 机器可以成为持续信号源
- 信号可以传播、衰减、聚合、被机器读取
- 导管提供一种特殊的无损传输手段

## 2. 当前系统分层

当前内容大体分为：

- 物流系统
- 生产系统
- 信号与导管系统

目前优先级最高的是信号系统和导管系统。

## 3. 信号系统总规则

### 3.1 信号基本属性

每个信号至少包含：

- 幅值
- 周期
- 相位
- 波形

当前实现中，系统运行在离散 tick 时间上，所以所谓“连续信号”本质上仍然是离散采样波形，而不是数学意义上的连续函数。

### 3.2 信号类型

当前分为两类：

- 脉冲信号
- 连续信号

#### 脉冲信号

- 典型来源：爆炸事件
- 持续时间：`1 tick`
- 在该 tick 内完成传播与结算

#### 连续信号

- 典型来源：机器
- 会持续存在，直到源被移除或参数发生变化
- 当前波形统一为方波

## 4. 传播规则

### 4.1 普通介质传播

普通介质包括空气和普通方块。当前规则下，它们统一视作普通传播介质。

规则如下：

- 信号可以穿墙传播
- 每传播 `1` 格，幅值衰减 `1`
- 传播代价按曼哈顿距离计算

传播代价公式：

`|dx| + |dy| + |dz|`

若信号初始幅值为 `A`，传播代价为 `d`，则到达目标后的有效幅值为：

`A - d`

当有效幅值小于等于 `0` 时，视为该信号不能影响目标。

### 4.2 导管传播

导管是特殊传播介质，其定位更接近“无损信号通道”。

规则如下：

- 导管内部传播无损
- 信号进入导管前和离开导管后，仍然按普通介质规则计算传播代价
- 同一个信号源到同一个目标，只取最佳传播路径，不会把“空气路径贡献”和“导管路径贡献”各算一份

这意味着：

- 空气直达和导管绕行之间会比较代价
- 最终只保留更优的那条路径

## 5. 导管与接口规则

### 5.1 导管不是六面漏风

导管不能把自身六个面都当成天然信号源或天然输入口。

收紧后的规则是：

- 导管本体只负责网络内部无损传输
- 导管不会自动与周围空气或普通方块连通信号
- 导管只能通过接口与外界交换信号

### 5.2 接口形式

接口不是独立方块，而是导管方块上的同格挂件。

每个导管有六个面状态：

- `interface_north`
- `interface_south`
- `interface_east`
- `interface_west`
- `interface_up`
- `interface_down`

规则如下：

- 一个面要么没有接口，要么有一个接口
- 已与另一根导管直接连通的面，不能安装接口
- 接口的输入输出面就是该面的外侧相邻格

### 5.3 外界连通条件

只有存在接口的面，才允许发生以下行为：

- 空气中的信号进入导管
- 导管中的信号输出到空气
- 导管与普通方块中的信号发生连通

没有接口的导管面，一律视为对外绝缘。

### 5.4 更新规则

接口增删必须触发：

- 导管方块状态刷新
- 邻居更新
- 相关接收端重算
- 导管网络缓存刷新

接口变化不仅是渲染变化，也必须实际改变导管网络的可进入/可输出面。

## 6. 连续信号采样规则

### 6.1 当前波形

当前只实现方波 `SQUARE`。

### 6.2 周期范围

当前连续信号周期允许范围：

- `2 tick`
- `4 tick`
- `6 tick`
- `8 tick`

### 6.3 采样规则

连续信号当前统一使用偶数周期离散方波，不再支持奇数周期。

采样规则如下：

- 前半周期采样为 `+A`
- 后半周期采样为 `-A`

示例：
- `2 tick`：`+A, -A`
- `4 tick`：`+A, +A, -A, -A`
- `6 tick`：`+A, +A, +A, -A, -A, -A`
- `8 tick`：`+A, +A, +A, +A, -A, -A, -A, -A`

这样做的目的：

- 保持方波定义统一
- 避免奇数周期补丁规则污染整体系统
- 让周期语义与采样语义完全一致

### 6.4 相位规则

连续信号源正式带有相位属性。

规则如下：

- 相位取值范围为 `0 ~ period-1`
- 相位参与当前 tick 的采样计算
- 相位不是默认固定为 `0`
- 当前实现中，相位由机器位置与源 id 稳定生成

这样做的目的：

- 避免所有同周期连续信号天然同相
- 让连续信号叠加结果真正体现波形系统特性
- 缓解“全偶数周期时等效值退化成锁相主导结果”的问题

## 7. 多信号聚合规则

### 7.1 聚合对象

对某个目标位置，系统会收集所有可以有效到达该位置的信号贡献。

机器默认只读取聚合后的单一结果，而不是分别读取所有源。

### 7.2 连续信号之间的聚合

若参与聚合的全部都是连续信号，则：

1. 求出它们周期的最小公倍数作为公共周期
2. 在公共周期内逐 tick 采样各自的瞬时值
3. 对每个采样点先做带符号求和
4. 再对和取绝对值
5. 最后对整个公共周期求平均

这个平均值就是机器读取到的等效值。

### 7.3 脉冲信号参与时的规则

若某个 tick 内有脉冲信号参与，则该 tick 按瞬时结算：

- 连续信号先按各自当前相位采样
- 脉冲信号按该 tick 的有效值参与
- 全部贡献做带符号求和
- 该 tick 结果按 `|sum|` 结算

这里不为脉冲额外构造跨 tick 的公共周期。

## 8. 机器读取规则

机器默认读取的是聚合后的最终结果。

当前关键读数：

- `equivalent_value`
- `instantaneous`
- `last_non_zero`

定义如下：

- `equivalent_value`：等效值
- `instantaneous`：当前 tick 的瞬时值
- `last_non_zero`：最近一次非零等效值

进一步约定：

- 纯连续信号场景下，等效值为公共周期内叠加波形绝对值的平均
- 当前 tick 混入脉冲信号时，该 tick 的瞬时结算结果可直接影响机器当前读数

## 9. 更新机制

当前信号系统采用“变化驱动更新”，而不是所有接收端每 tick 主动全量轮询。

世界中的信号状态由每个 `ServerLevel` 独立拥有的 `SignalRuntime` 管理。信号源仓库、接收端索引、导管网络缓存、聚合缓存、瞬时影响记录与延迟刷新队列均属于当前维度，不使用只按维度资源键区分存档的全局单例。

触发重算的情况包括：

- 爆炸事件发生
- 持续信号源参数变化
- 持续信号源被放置、更新或移除
- 导管被放置或拆除
- 接口被安装或拆除
- 导管网络连通性变化

更新原则：

- 只重算受影响的接收端
- 导管网络变化需要刷新缓存
- 脉冲消失也算一次变化
- 连续信号源或拓扑变化时，重建当前维度内可能持续受影响的目标集合
- 脉冲、连续源变化和拓扑变化产生的刷新目标先合并去重，再在世界 tick 末统一结算
- 接收端只负责注册、注销和处理聚合结果，不自行运行信号刷新 ticker
- 未加载区块不被主动扫描；已加载但不再是接收端的位置会从索引中移除

每个世界 tick 的集中处理顺序为：

1. 清理上一 tick 的瞬时信号源与聚合贡献
2. 收集上一 tick 脉冲消失后需要恢复或清零的目标
3. 合并导管与接口变化产生的延迟刷新目标
4. 合并当前连续信号活动目标
5. 对已加载接收端去重刷新，并清理失效索引

`SignalRuntime` 使用非持久化 Level Attachment。它只保存能够从当前世界重新推导的临时状态，维度卸载或服务器停止时统一清理，不写入存档。

## 10. 当前已落实的关键实现约束

以下规则已经进入实现，不应轻易回退：

- 导管采用“同格挂件接口”方案，不再使用独立接口方块
- 导管只能通过接口与外界信号连通
- 同一信号源到同一目标只取最佳路径
- 检测器第一项显示的是等效值，不是简单意义上的“当前值”
- 连续信号只保留偶数周期
- 连续信号相位是正式规则，不再默认全部为 0
- `CISignalSourceTypes` 只负责全局只读的信号源类型声明，不持有世界运行状态
- 所有世界信号服务通过当前 `ServerLevel` 获取对应的 `SignalRuntime`
- 信号仓库、接收端索引、聚合缓存和导管缓存均为单维度对象
- 生态瓶与检测器不再拥有独立的信号刷新 ticker
- 方块实体加载与卸载必须成对注册、注销信号源或接收端
- 维度卸载与服务器停止必须释放完整信号运行时

## 11. 后续实现建议

接下来继续开发时，优先级建议如下：

1. 继续验证大型导管网络频繁变更时的正确性与性能
2. 检查连续信号、多个脉冲与拓扑变化同 tick 发生时的聚合结果
3. 验证区块卸载、维度卸载和连续切换存档时不存在遗留运行状态
4. 逐步让占位机器通过 `SignalRuntimeAccess` 接入真实信号驱动逻辑
